## 0. Минимум за 5 минут

**Что сделано.** Из двух вариантов задания выбран второй — **самостоятельная реализация** (готовые библиотеки дают не больше 70 баллов). Без библиотек написаны:
- QR-код по стандарту ISO/IEC 18004: версии 1–40, уровни коррекции L/M/Q/H, режимы цифровой, буквенно-цифровой и байтовый (UTF-8, кириллица);
- арифметика поля Галуа GF(256), код Рида–Соломона (кодирование и **исправление** ошибок), маски, служебная информация;
- **декодер** QR-кода и **сканер** картинки (поиск трёх шаблонов поиска, бинаризация, выборка модулей);
- штрих-коды **EAN-13** и **Code 128** со сканером;
- 10 видов повреждений («почеркать, изменить цвета, размыть, отрезать углы» из методички и другие) и серии опытов.

**Как доказана правильность:**
- матрицы совпадают с эталонной библиотекой `qrcode` бит в бит (все 40 версий × 4 уровня);
- коды читает независимый сканер OpenCV (60 из 60);
- EAN-13 совпадает с `python-barcode` (300 из 300);
- 20 автотестов, включая известный пример «HELLO WORLD».

**Шесть идей, которые нужно понимать:**

1. **Штрих-код** — одномерный: информация в ширинах штрихов и пробелов. Ошибки он только **обнаруживает** контрольной цифрой, а не исправляет. Устойчивость даёт высота штрихов: хватит одной целой строки сканирования.
2. **QR-код** — двумерный. Его надёжность обеспечивает **код Рида–Соломона**: к данным добавляются байты коррекции, и код исправляет до половины их числа испорченных байтов в каждом блоке. Уровни L/M/Q/H восстанавливают примерно 7/15/25/30 % байтов.
3. Рид–Соломон работает в **поле Галуа GF(2⁸)**: байты складываются как XOR, а умножаются как многочлены по модулю x⁸ + x⁴ + x³ + x² + 1. Это тот же циклический код из ЛР3, только «буквы» — байты.
4. **Чередование блоков** растягивает одну кляксу на все блоки понемногу, а **маска** убирает большие одноцветные пятна и ложные шаблоны поиска.
5. **Шаблоны поиска** в трёх углах нужны, чтобы найти код и определить его размер и поворот. Испорти один — код не найдётся, даже если данные целы. Поэтому срезанный левый верхний угол убивает код сразу, а правый нижний (там шаблона нет) — только при срезе в 40–70 % стороны.
6. Сканер видит только **яркость**. Цвета неважны, пока тёмные модули заметно темнее светлых. Инверсию сканер берёт, если пробует обе полярности.

## 1. Штрих-коды EAN-13 и Code 128

### 1.1. Общие понятия

**Модуль** — самая узкая полоса (штрих или пробел). Ширины всех полос кратны модулю. Вокруг кода обязательна **светлая зона** (quiet zone): по ней сканер понимает, где код начинается.

Штрих-код **одномерный**: вся информация вдоль одной строки, высота штрихов лишь дублирует её. Поэтому сканеру достаточно одной неповреждённой строки.

### 1.2. EAN-13

13 цифр: страна/производитель/товар (Россия — 460–469) и **контрольная цифра**.

Строение (95 модулей):

| Часть | Модулей | Узор |
|---|---|---|
| левый ограничитель | 3 | 101 |
| 6 цифр (наборы L или G) | 6 × 7 | каждая цифра — 2 штриха и 2 пробела |
| центральный ограничитель | 5 | 01010 |
| 6 цифр (набор R) | 6 × 7 | |
| правый ограничитель | 3 | 101 |

**Наборы.** Код цифры в наборе R — инверсия L (0 ↔ 1), G — это R, записанный задом наперёд. У L нечётное число тёмных модулей, у G — чётное. Благодаря этому:
- сканер понимает направление чтения (справа налево цифры выглядят иначе);
- **первая цифра не рисуется**: она задаётся тем, какие из 6 левых цифр записаны L, а какие G (таблица чётности: 0 → LLLLLL, 4 → LGLLGG и т. д.).

**Контрольная цифра.** Цифры на нечётных местах берутся с весом 1, на чётных — с весом 3:

$$S=\sum_{i=1}^{12} w_i d_i,\quad w_i\in\{1,3\},\qquad d_{13}=(10-S \bmod 10)\bmod 10.$$

Пример: 400638133393 → S = 89 → контрольная 1 → **4006381333931**.

Свойства:
- **любая ошибка в одной цифре обнаруживается.** Цифра d с весом w превращается в d′, сумма меняется на w(d′ − d). При w = 1 это число от 1 до 9 по модулю, при w = 3 — кратное 3 и не кратное 10, потому что 3 и 10 взаимно просты. В обоих случаях оно не делится на 10;
- **перестановка соседних цифр** a, b меняет сумму на 2(b − a). Она не обнаруживается только при |a − b| = 5;
- исправить ошибку код не может — только сказать «неверно».

### 1.3. Code 128

- Любые символы ASCII 32–126 (латиница, цифры, знаки; кириллицы нет).
- Каждый символ — **3 штриха и 3 пробела, суммарная ширина 11 модулей**, ширины 1–4. Стоп-символ — 13 модулей.
- 107 символов: 0–102 — данные и служебные, 103–105 — старт A/B/C, 106 — стоп.
- **Набор B:** значение = код ASCII − 32. **Набор C:** пара цифр 00–99 — один символ, то есть числа записываются вдвое плотнее. Переключение: 99 — «перейти в C», 100 — «перейти в B».
- **Контрольный символ:**

$$\text{check}=\Bigl(v_0+\sum_{i=1}^{n} i\cdot v_i\Bigr)\bmod 103,$$

где v₀ — стартовый символ, i — номер символа данных. Модуль 103 — простое число, поэтому взвешенная сумма ловит и замену символа, и перестановку двух соседних.

## 2. Математика QR-кода: поле GF(256) и код Рида–Соломона

### 2.1. Поле Галуа GF(2⁸)

**Поле** — множество, где можно складывать, вычитать, умножать и делить (кроме деления на 0) по обычным правилам. В QR элементы поля — **байты 0…255**. Биты байта — коэффициенты многочлена степени ≤ 7 над GF(2), как в ЛР3:

$$\texttt{10000011}\ \leftrightarrow\ x^7+x+1.$$

- **Сложение = вычитание = XOR**: коэффициенты складываются по модулю 2.
- **Умножение** — умножение многочленов, затем остаток от деления на неприводимый многочлен

$$p(x)=x^8+x^4+x^3+x^2+1\quad(\texttt{0x11D}).$$

Он неприводим, поэтому результат снова байт и у каждого ненулевого байта есть обратный.

**Примитивный элемент α = 2** (то есть многочлен x): его степени α⁰ = 1, α¹ = 2, α² = 4, …, α⁸ = 29, …, α²⁵⁴ перебирают **все 255** ненулевых байтов, а α²⁵⁵ = 1. Каждый ненулевой байт — это αᵏ, отсюда таблицы:

$$\mathrm{EXP}[k]=\alpha^k,\qquad \mathrm{LOG}[a]=k\ \text{при}\ \alpha^k=a,\qquad a\cdot b=\alpha^{(\log a+\log b)\bmod 255}.$$

Почему α⁸ = 29: x⁸ ≡ x⁴ + x³ + x² + 1 (mod p), а 00011101₂ = 29. Программа проверяет таблицы, сравнивая с умножением «в столбик» (`mul_slow`) для всех пар.

### 2.2. Код Рида–Соломона

Это **циклический код** из ЛР3, только символ — байт. Блок из k байтов данных D(x) дополняется n байтами коррекции:

$$g(x)=\prod_{i=0}^{n-1}(x-\alpha^i),\qquad R(x)=D(x)\,x^n \bmod g(x),\qquad C(x)=D(x)\,x^n+R(x).$$

C(x) делится на g(x), значит C(αⁱ) = 0 при i = 0…n − 1. Это те же шаги, что в ЛР3: приписать n нулей, поделить, приписать остаток.

**Почему исправляется ⌊n/2⌋ байтов.** Код Рида–Соломона — **МДР-код** (максимальное расстояние разделимый): его минимальное расстояние достигает границы Синглтона,

$$d_0=n_{\text{всего}}-k+1=n+1.$$

Значит, он обнаруживает n ошибочных байтов и **исправляет** ⌊(d₀ − 1)/2⌋ = ⌊n/2⌋, как в ЛР3. Ошибка в байте считается одной ошибкой, сколько бы бит в нём ни испортилось. Поэтому код хорошо переносит **пачки**: клякса портит много соседних бит, но мало байтов.

**Исправление** (что делает `reed_solomon.decode`):
1. **Синдромы** Sᵢ = r(αⁱ), i = 0…n − 1. Все нули — ошибок нет. Синдромы зависят только от ошибки: Sᵢ = E(αⁱ) = Σ Yₖ Xₖⁱ, где Xₖ = α^{pₖ} — «локатор» (место ошибки), Yₖ — её величина.
2. **Алгоритм Берлекэмпа–Мэсси** находит многочлен локаторов Λ(x) = ∏(1 − Xₖx) наименьшей степени, согласованный с синдромами. Степень Λ равна числу ошибок.
3. **Поиск Ченя**: перебираем все позиции p и проверяем Λ(α⁻ᵖ) = 0. Корни дают номера испорченных байтов. Если корней меньше, чем степень Λ, ошибок больше ⌊n/2⌋ — сообщаем «не могу исправить».
4. **Алгоритм Форни**: величина ошибки

$$Y_k=X_k\,\frac{\Omega(X_k^{-1})}{\Lambda'(X_k^{-1})},\qquad \Omega(x)=S(x)\Lambda(x)\bmod x^{n},$$

где Λ′ — формальная производная (в характеристике 2 остаются только нечётные степени). Байт исправляется операцией XOR с Yₖ.
5. Проверка: после исправления все синдромы нулевые.

Пример из теста: «HELLO WORLD» версии 1-M — байты коррекции 196 35 39 119 235 215 231 226 93 23, как в описаниях стандарта.

### 2.3. Коды служебной информации

- **Формат** (уровень + маска, 5 бит) защищён **БЧХ-кодом (15,5)** с образующим многочленом x¹⁰ + x⁸ + x⁵ + x⁴ + x² + x + 1. Затем XOR с маской 101010000010010, чтобы служебная информация не была нулевой. Расстояние кода 7 — исправляет до 3 ошибочных бит. Декодер просто ищет ближайшее из 32 допустимых значений. Копий две.
- **Номер версии** (с 7-й версии) — код **(18,6)** с многочленом x¹² + x¹¹ + x¹⁰ + x⁹ + x⁸ + x⁵ + x² + 1, тоже исправляет до 3 ошибок, две копии.

## 3. Как строится QR-код

**1. Анализ данных.** Выбирается самый плотный режим, в который помещается текст:
- цифровой — 3 цифры в 10 бит;
- буквенно-цифровой — пара символов из 45 (0–9, A–Z, пробел, $%*+-./:) записывается числом 45·a + b в 11 бит;
- байтовый — байт в 8 бит; кириллица идёт в UTF-8, 2 байта на букву.

Затем выбирается наименьшая **версия** v (сторона n = 17 + 4v модулей), в которую помещаются данные при выбранном уровне.

**2. Поток бит:**
- индикатор режима (4 бита: 0001, 0010, 0100);
- число символов (8–16 бит в зависимости от режима и версии);
- данные;
- терминатор 0000, дополнение нулями до целого байта;
- байты-заполнители 11101100, 00010001 по очереди до ёмкости версии.

**3. Блоки и коррекция.** Данные делятся на блоки (по таблице стандарта), к каждому добавляются байты Рида–Соломона.

**4. Чередование.** В матрицу пишутся сначала 1-е байты всех блоков, затем 2-е и т. д. Соседние байты матрицы принадлежат разным блокам, и клякса распределяется по всем блокам.

**5. Матрица.**
- 3 шаблона поиска 7×7 с отношением 1:1:3:1:1 и светлыми разделителями;
- синхронизирующие линии (строка и столбец 6) — по ним считается шаг сетки;
- выравнивающие узоры 5×5 (с версии 2);
- место под служебную информацию и номер версии, тёмный модуль.

Данные укладываются парами столбцов справа налево «змейкой» вверх-вниз, столбец 6 пропускается.

**6. Маска.** Каждая из 8 масок инвертирует модули данных, где формула от строки i и столбца j истинна, например (i + j) mod 2 = 0. Для каждой считается **штраф**:
- **N1:** 3 + (L − 5) за каждую серию длины L ≥ 5 одного цвета;
- **N2:** 3 за каждый одноцветный квадрат 2×2;
- **N3:** 40 за каждый узор 1011101 с четырьмя светлыми модулями сбоку — он похож на шаблон поиска;
- **N4:** 10·k, где k = ⌊|доля тёмных − 50 %| / 5 %⌋.

Выбирается маска с наименьшей суммой.

**7. Служебная информация** записывается дважды около шаблонов поиска.

Емкость при уровне H меньше, а надёжность выше. Например, наш текст из 111 байт занимает версию 6 при L, 7 при M, 9 при Q, 10 при H.

## 4. Как программа читает код с картинки

1. **Яркость** каждого пикселя: Y = 0,299R + 0,587G + 0,114B. Цвет сканер не видит.
2. **Медианный фильтр 3×3** (попытка «с фильтром») — каждый пиксель заменяется медианой соседей, одиночные точки шума исчезают.
3. **Бинаризация.** Порог — середина между уровнями тёмного (2-й процентиль) и светлого (98-й). Запасной вариант — **порог Оцу**: перебираем порог t и берём тот, при котором максимальна межклассовая дисперсия σ²ₘₑₖ = w₀w₁(μ₀ − μ₁)². Если лучших порогов «плато», берётся его середина.
4. **Поиск шаблонов поиска.** В каждой строке ищутся 5 подряд серий «тёмный–светлый–тёмный–светлый–тёмный» с отношением ширин **1:1:3:1:1** (допуск ±60 %). Найденное перепроверяется по вертикали и снова по горизонтали — через несколько точек центрального квадрата 3×3, чтобы одна линия ручки не сорвала проверку. Кандидаты объединяются в кластеры.
5. **Выбор тройки**: три кандидата должны образовывать **прямоугольный равнобедренный треугольник** с одинаковым размером модуля. Вершина при прямом угле — левый верхний; знак векторного произведения отличает правый верхний от левого нижнего (это даёт поворот).
6. **Размер**: n ≈ сторона / модуль + 7, округляется до вида 17 + 4v. Если чтение не удалось, пробуются соседние размеры n ± 4, n ± 8.
7. **Сетка**: центр модуля (строка r, столбец c) = TL + (c − 3)·u + (r − 3)·v, где u и v — шаги сетки. Это аффинное преобразование, поэтому поворот учитывается. Средняя яркость вокруг центра считается сразу для всех модулей через интегральное изображение.
8. Всё повторяется для **инвертированной** картинки (светлый код на тёмном фоне).

**Штрих-код** читается по 25 горизонтальным строкам, без фильтра и с медианным фильтром. В каждой строке измеряются ширины полос, нормируются и сравниваются с таблицами. Ответ, который дали больше всего строк, побеждает. Контрольная цифра отбрасывает неверные чтения.

## 5. Анализ помехоустойчивости: опыты и выводы

Условия: один и тот же текст (111 байт) на **версии 10** для всех уровней, чтобы размер кода был одинаковым, 6 пикселей на модуль. Для случайных повреждений (линии, шум) — по 10 попыток, для остальных — по одной.

### 5.1. Проверка теории Рида–Соломона

Случайно портятся целые байты матрицы:

| Уровень | Может исправить (Σ⌊n/2⌋ / всего) | 100 % чтений до | Ни одного чтения с |
|---|---|---|---|
| L (4 блока по 18 байтов коррекции) | 36 / 346 = 10,4 % | 4 % | 10 % |
| M (5 × 26) | 65 / 346 = 18,8 % | 8 % | 20 % |
| Q (8 × 24) | 96 / 346 = 27,7 % | 14 % | 26 % |
| H (8 × 28) | 112 / 346 = 32,4 % | 16 % | 30 % |

**Вывод.** Код ломается немного **раньше** теоретической доли: случайные ошибки распределяются по блокам неравномерно, а предел ⌊n/2⌋ действует на **каждый блок отдельно**. Выше теоретической доли не читается никогда — это подтверждает теорию.

### 5.2. Повреждения изображения

| Повреждение | L | M | Q | H | Почему так |
|---|---|---|---|---|---|
| Клякса/логотип в центре (доля площади, 100 % чтений) | 7,5 % | 12,5 % | 20 % | 22,5 % | работает Рид–Соломон: на 22,5 % у H исправлено 98 байтов из 112 возможных |
| Почеркать ручкой (линий без единой неудачи) | 0 | 2 | 4 | 4 | линии рассыпаны по всему коду, портят много байтов понемногу |
| Срезать правый нижний угол (катет / сторона) | 40 % | 50 % | 60 % | 70 % | там нет шаблона поиска — теряются только данные |
| Срезать левый верхний угол | 5 % | 5 % | 5 % | 5 % | срезан шаблон поиска — код не найден, уровень не помогает |
| Размыть (радиус / сторона кода) | 0,75 % | 0,75 % | 0,75 % | 0,75 % | размытие стирает одиночные модули по всему коду сразу |
| Снизить контраст | до 98 % | до 98 % | до 98 % | до 98 % | порог-середина работает при любом контрасте |
| Цвета (синий на жёлтом), инверсия | читается | читается | читается | читается | важна только разница яркостей |
| Шум «соль и перец» | до 20 % | до 20 % | до 20 % | до 20 % | медианный фильтр убирает точки |
| Поворот | до 34° | до 34° | до 34° | до 34° | шаблоны поиска не зависят от поворота |

**Сравнение с независимым сканером OpenCV** (ArUco-детектор) на тех же картинках:
- одинаково — клякса, срез правого нижнего угла, размытие, цвета, контраст;
- наш сканер лучше на шуме (у OpenCV нет медианного фильтра), на инверсии (OpenCV не пробует светлый код на тёмном фоне) и на линиях ручки;
- OpenCV лучше при повороте на 45° для плотного кода.

**Штрих-коды:**
- **EAN-13** выдержал всё, кроме линий: кляксу до 20 %, размытие, шум до 30 %, поворот до 9°. Линии ручки, перечёркивающие все строки сканирования, ломают его: 70 % чтений при 4 линиях, 0 % при 16.
- **Code 128** чувствительнее: при той же длине полосы уже, отказ при кляксе 20 % и сильном размытии.
- У штрих-кода **нет исправления ошибок**: защищают только высота штрихов (хватит одной целой строки) и контрольная цифра (неверное чтение отбрасывается).

**Итоговые выводы:**
1. Уровень коррекции решает, когда повреждена **область данных** (клякса, логотип, срез угла без шаблона): H выдерживает втрое больше, чем L.
2. Уровень **не помогает**, если повреждены **служебные элементы** (шаблоны поиска) или вся картинка сразу (размытие). Поэтому логотип ставят в центр, а не в угол, и печатают код с запасом по размеру.
3. Цвет неважен — важен контраст яркостей.
4. Чем выше уровень, тем больше версия при том же тексте и тем мельче модули при той же площади. Это делает код чувствительнее к размытию — плата за коррекцию.

## 7. Вопросы преподавателя и ответы

### Штрих-коды

**1. Чем штрих-код отличается от QR-кода?**
Штрих-код одномерный: информация только в ширинах полос вдоль одной линии, ёмкость — десятки символов, ошибки только обнаруживаются. QR-код двумерный: до 2953 байт (версия 40, уровень L), ошибки исправляются кодом Рида–Соломона.

**2. Как устроен EAN-13?**
95 модулей: ограничители 101, 01010, 101 и 12 цифр по 7 модулей (два штриха и два пробела). Левые цифры — наборы L/G, правые — R. 13-я цифра контрольная.

**3. Как вычисляется контрольная цифра EAN-13 и что она ловит?**
Сумма цифр с весами 1, 3, 1, 3, …; контрольная дополняет сумму до кратного 10. Ловит любую ошибку в одной цифре (3 и 10 взаимно просты) и перестановку соседних цифр, кроме случая |a − b| = 5.

**4. Почему первая цифра EAN-13 не нарисована штрихами?**
Она закодирована выбором наборов L/G для шести левых цифр (таблица чётности). Так EAN-13 совместим с 12-значным американским UPC-A: у него первая цифра 0, то есть все левые цифры в наборе L.

**5. Как сканер понимает направление чтения?**
Цифры набора L имеют нечётное число тёмных модулей, G и R — чётное. При чтении задом наперёд схема чётности не совпадёт.

**6. Что такое Code 128 и наборы A/B/C?**
Каждый символ — 3 штриха и 3 пробела шириной 11 модулей. Набор B — печатные символы ASCII, набор C — пары цифр (вдвое плотнее), набор A — заглавные и управляющие символы. Контрольный символ — взвешенная сумма по модулю 103.

**7. Почему штрих-код выдерживает кляксу, но не выдерживает линию поперёк?**
Информация повторяется по высоте: клякса закрывает часть строк, а другие строки целы. Линия, перечёркивающая весь код по высоте, портит все строки сразу.

### QR-код: математика

**8. Что такое поле Галуа GF(256)?**
Множество из 256 байтов со сложением XOR и умножением многочленов по модулю неприводимого p(x) = x⁸ + x⁴ + x³ + x² + 1. Каждый ненулевой элемент имеет обратный, поэтому можно делить.

**9. Зачем нужен неприводимый многочлен?**
Чтобы остатки по модулю p образовывали поле: если бы p раскладывался, нашлись бы ненулевые a, b с a·b = 0, и деление стало бы невозможным (как по модулю составного числа).

**10. Что такое примитивный элемент α?**
Элемент, степени которого перебирают все 255 ненулевых элементов. В QR α = 2 (многочлен x). Благодаря ему умножение сводится к сложению логарифмов.

**11. Как устроен код Рида–Соломона?**
Циклический код над GF(256) с образующим g(x) = ∏(x − αⁱ). Байты коррекции — остаток от деления D(x)·xⁿ на g(x). Кодовое слово делится на g(x), то есть обращается в ноль при x = α⁰…αⁿ⁻¹.

**12. Сколько ошибок исправляет код Рида–Соломона и почему?**
До ⌊n/2⌋ испорченных байтов при n байтах коррекции. Это МДР-код: d₀ = n + 1 (граница Синглтона достигается), исправляет ⌊(d₀ − 1)/2⌋. Если известно, *где* байт испорчен (стирание), исправляются до n стираний: 2·ошибки + стирания ≤ n.

**13. Как находятся ошибки?**
Синдромы Sᵢ = r(αⁱ) → Берлекэмп–Мэсси даёт многочлен локаторов Λ(x) → поиск Ченя находит его корни (места ошибок) → алгоритм Форни вычисляет величины ошибок → XOR.

**14. Почему Рид–Соломон хорош против клякс?**
Ошибкой считается испорченный байт целиком, сколько бы бит в нём ни было. Клякса портит много бит, но они сгруппированы в немногих байтах.

**15. Что означают уровни L, M, Q, H?**
Примерную долю байтов, которую можно восстановить: 7, 15, 25 и 30 %. На версии 10 у нас точно: 10,4 / 18,8 / 27,7 / 32,4 %.

**16. Почему в опыте код ломается раньше теоретической доли?**
Предел ⌊n/2⌋ действует в каждом блоке отдельно, а случайные ошибки распределяются по блокам неравномерно: какой-то блок получает больше своего предела, хотя в сумме ошибок меньше.

**17. Зачем чередование блоков?**
Чтобы соседние байты в матрице принадлежали разным блокам. Тогда клякса распределяется по всем блокам понемногу, а не выводит из строя один блок.

**18. Как защищена служебная информация?**
БЧХ-кодом (15,5) с расстоянием 7 (исправляет 3 бита) и записана дважды. Номер версии — кодом (18,6), тоже две копии.

### QR-код: построение

**19. Какие режимы кодирования бывают и зачем?**
Цифровой (3,33 бита на цифру), буквенно-цифровой (5,5 бита на символ), байтовый (8 бит), кандзи. Чем уже алфавит, тем плотнее запись и тем меньше нужная версия.

**20. Что такое версия?**
Размер: n = 17 + 4v модулей, v = 1…40, от 21×21 до 177×177.

**21. Зачем шаблоны поиска и почему отношение 1:1:3:1:1?**
По трём шаблонам сканер находит код, его размер и поворот. Отношение одинаково вдоль любой прямой через центр при любом повороте и масштабе. Маска штрафует похожие узоры в данных, чтобы не было ложных срабатываний.

**22. Зачем синхронизирующие линии и выравнивающие узоры?**
Синхронизирующие — чтобы определить шаг сетки (сколько модулей и где их центры). Выравнивающие — чтобы поправить сетку при изгибе бумаги и перспективе в больших версиях.

**23. Зачем маска и как её выбирают?**
Маска убирает большие одноцветные области и ложные шаблоны поиска, которые мешают сканеру. Перебираются 8 масок, считается штраф по правилам N1–N4, берётся наименьший.

**24. Как данные укладываются в матрицу?**
Парами столбцов справа налево, «змейкой» вверх и вниз, в обход служебных модулей. Столбец 6 (синхронизирующий) пропускается.

### Сканер и опыты

**25. Как программа находит QR-код на картинке?**
Яркость → медианный фильтр → порог → поиск серий 1:1:3:1:1 по строкам с перепроверкой по столбцам → тройка шаблонов, образующая прямоугольный равнобедренный треугольник → сетка модулей → выборка → декодер.

**26. Что такое порог Оцу?**
Порог бинаризации, максимизирующий межклассовую дисперсию w₀w₁(μ₀ − μ₁)²: тёмные и светлые пиксели разделяются наилучшим образом. Мы используем ещё и середину между уровнями тёмного и светлого, потому что на размытом изображении она устойчивее.

**27. Почему цвет кода неважен, а контраст важен?**
Сканер переводит картинку в яркость Y = 0,299R + 0,587G + 0,114B. Синий на жёлтом даёт тёмный на светлом и читается. Жёлтый на белом — почти одна яркость, и код не прочитается.

**28. Почему срезанный левый верхний угол губит код, а правый нижний — нет?**
В левом верхнем углу шаблон поиска: без него код не найти и не определить ориентацию. Уровень коррекции тут не помогает. В правом нижнем углу шаблона нет, теряются только данные, и их восстанавливает Рид–Соломон: при H — до 70 % стороны.

**29. Почему размытие одинаково губит все уровни?**
Размытие портит одиночные модули по всему коду сразу — сотни байтов, больше любого предела коррекции. Помогает только больший размер модуля (меньшая версия или крупнее печать).

**30. Можно ли поставить логотип в центр QR-кода?**
Да, если выбрать уровень H (или Q) и закрыть не больше ~20 % площади: в нашем опыте H читался с кляксой 22,5 %, исправив 98 байтов из 112 возможных.

**31. Почему наш сканер читает инверсию, а OpenCV — нет?**
Мы пробуем обе полярности: если код не найден, инвертируем картинку и пробуем снова. Стандарт разрешает инверсию (зеркальное/инвертированное отображение) как дополнительную возможность.

**32. Как проверили, что QR-код построен правильно?**
- матрицы совпадают с библиотекой `qrcode` бит в бит для всех 40 версий и 4 уровней;
- OpenCV читает 60 кодов из 60;
- байты «HELLO WORLD» совпадают с примером из описаний стандарта;
- 20 автотестов.

## 8. Шпаргалка формул

| Что | Формула |
|---|---|
| Контрольная цифра EAN-13 | d₁₃ = (10 − Σwᵢdᵢ mod 10) mod 10, wᵢ = 1, 3, 1, 3, … |
| Контрольный символ Code 128 | (v₀ + Σ i·vᵢ) mod 103 |
| Многочлен поля | p(x) = x⁸ + x⁴ + x³ + x² + 1 (0x11D), α = 2 |
| Умножение в GF(256) | a·b = α^((log a + log b) mod 255), a ⊕ b — сложение |
| Образующий Рида–Соломона | g(x) = ∏ᵢ₌₀ⁿ⁻¹ (x − αⁱ) |
| Кодирование | R(x) = D(x)·xⁿ mod g(x), C = D·xⁿ + R |
| Исправляет | t = ⌊n/2⌋ байтов в блоке; 2t + стирания ≤ n; d₀ = n + 1 |
| Синдромы | Sᵢ = r(αⁱ), i = 0…n − 1 |
| Форни | Yₖ = Xₖ·Ω(Xₖ⁻¹)/Λ′(Xₖ⁻¹), Ω = S·Λ mod xⁿ |
| Размер QR | n = 17 + 4v модулей |
| Штраф маски | N1 = 3 + (L − 5); N2 = 3 за 2×2; N3 = 40; N4 = 10·⌊\|p − 50\| / 5⌋ |
| Яркость | Y = 0,299R + 0,587G + 0,114B |
| Порог Оцу | max w₀w₁(μ₀ − μ₁)² |
| Шаблон поиска | 1:1:3:1:1 |
